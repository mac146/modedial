This diff isn't a refactor. It changes behavior and adds bugs.

**Bugs**
1. **Off-by-one:** `i <= items.length` reads `items[items.length]`, which is `undefined`, so it throws a `TypeError` on every call.
2. **SQL injection:** building the query by string concatenation is unsafe. Use a parameterized query: `db.query("UPDATE orders SET total = ? WHERE id = ?", [total, orderId])`. The placeholder syntax depends on your driver.
3. **New behavior:** the 10% discount over 100 is a feature, not a tidy-up. It also uses a magic number and applies no rounding. If it's wanted, it belongs in a separate PR with tests.
4. **Regression in readability:** the original `reduce` was already correct and concise. The loop adds mutation and the bug above for no gain.

**Suggested tidy version (behavior-preserving)**
```js
const total = items.reduce((sum, { price, qty }) => sum + price * qty, 0);
db.query("UPDATE orders SET total = ? WHERE id = ?", [total, orderId]);
```
Keep the discount out unless it's intended. If it is, add it separately with a named constant.
