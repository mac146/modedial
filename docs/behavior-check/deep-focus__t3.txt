Goal: Review the PR diff that replaces the `reduce` total with a loop, adds a discount, and writes the total to the DB.

**Blocking issues**

1. **Off-by-one crash.** `i <= items.length` reads `items[items.length]`, which is `undefined`. `.price` then throws a `TypeError` on every call. Use `i < items.length`, or keep the original `reduce`.
2. **SQL injection.** The query is built by string concatenation with `orderId`. If `orderId` comes from user input, an attacker can run arbitrary SQL. Use a parameterized query instead, for example `db.query("UPDATE orders SET total = ? WHERE id = ?", [total, orderId])`. The placeholder syntax depends on your driver.

**Should fix**

3. **Discount with a magic number.** `100` and `0.9` are unexplained, so name them as constants. `total * 0.9` also produces floating-point noise such as `89.99999999`. Round to cents or compute in integer cents. Confirm whether the discount should apply before or after tax and shipping.
4. **Needless rewrite.** The original `reduce` was correct and shorter. The loop adds nothing except the bug.
5. **Edge cases.** There is no handling for empty or null `items`, a negative `qty`, or a missing `price`. There are also no tests. Add tests for the empty cart, the exactly-100 boundary, and the discounted case.

**Verdict:** Request changes. Items 1 and 2 must be fixed before merge.
