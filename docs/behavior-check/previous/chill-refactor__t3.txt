This diff isn't a behavior-preserving refactor, and it has real bugs.

**Blocking**
1. **Off-by-one crash:** `i <= items.length` reads `items[items.length]`, which is `undefined`. That throws a `TypeError` on every call. Use `<` or `for...of`.
2. **SQL injection:** the query is built by string concatenation with `orderId` (and `total`). Use a parameterized query, e.g. `db.query("UPDATE orders SET total = ? WHERE id = ?", [total, orderId])`. Use the placeholder style your driver expects.

**Scope problems**
3. **Unrequested discount:** `if (total > 100) total *= 0.9` is a new feature, not a tidy-up. It needs its own PR, a spec, and tests. Floating-point money math should also be rounded or done in cents.
4. **Unrequested DB write:** the `UPDATE` adds a side effect to what was a pure calculation. Keep the calculation separate from persistence.
5. **Worse loop:** the original `reduce` was already clear. The hand-rolled loop adds the bug and no benefit.

**Suggested shape**
```js
const total = items.reduce((sum, { price, qty }) => sum + price * qty, 0);
```
Keep the original line, which already does what's needed. If the discount and DB update are wanted, add them in a separate, tested change with a parameterized query.

**Tests:** I see none in this diff. Before touching this area, add tests for an empty cart, a single item, and the 100 boundary if the discount stays.
